# Why the generated language-client typings look unusual

The `typings.vscodeLanguageclient` package is generated by ScalablyTyped, not
hand-authored Scala. The converter reads npm packages from `node_modules` and
writes generated sources into sbt's target cache; its plugin implementation is
in [`src-ref/converter`](../src-ref/converter/). The plugin is enabled and the
client dependency is declared in [`build.sbt`](../build.sbt).

## Namespaces follow TypeScript modules

ScalablyTyped maps package modules and declaration paths into Scala packages:

- `typings.vscodeLanguageclient.mod` represents the package-level API.
- `typings.vscodeLanguageclient.libCommonClientMod` comes from declarations
  under `lib/common/client`.
- Names such as `anon` and `vscodeLanguageclientStrings` represent generated
  structural types and string-literal types.

TypeScript unions and optional fields are represented with Scala.js types such
as `|` and `js.UndefOr`. This preserves the source API, but the result is not
necessarily an idiomatic Scala API.

## Why some Node APIs are missing

In `vscode-languageclient` 9.0.1, its
[`package.json`](../node_modules/vscode-languageclient/package.json) sets
`typings` to `lib/common/api.d.ts`, while the runtime entry point is
`lib/node/main.js`.
The Node-specific declarations are in `lib/node/main.d.ts` and are reached
through the `vscode-languageclient/node` subpath. The generated package
therefore provides much of the common client API, but may not provide the
Node-specific `LanguageClient` and transport declarations used by this
extension.

The converter is doing a mechanical translation of the declarations it
imports; it does not design a single, simplified facade for both entry points.
Reuse generated common types such as `BaseLanguageClient` and
`LanguageClientOptions` where they fit, and keep any hand-written facade focused
on the Node entry point's missing types.

Generated files live under `target/streams/.../stImport/.../sources`; do not
edit them directly. Change the source TypeScript declarations or the Scala
facade instead.
